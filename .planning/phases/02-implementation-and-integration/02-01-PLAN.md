   ```typescript
   export interface ValidateOpenid4vpExpectedUrlOptions {
     /**
      * The OpenID4VP request from the IAE response
      */
     openid4vpRequest: Openid4vpRequest

     /**
      * The URL where follow-up request will be sent
      * (typically the interactive_authorization_endpoint)
      */
     followUpRequestUrl: string

     /**
      * Callbacks for JWT verification
      */
     callbacks: Pick<CallbackContext, 'verifyJwt'>

     /**
      * JWK or JWK set for verifying the signed request
      */
     signerJwk?: Jwk | JwkSet
   }

   export interface ValidateOpenid4vpExpectedUrlResult {
     valid: boolean
     error?: string
     errorDescription?: string
   }
   ```

2. Implement validateOpenid4vpExpectedUrl function:
   - If `openid4vpRequest.request` is undefined (unsigned), return `{ valid: true }` (PROT-06)
   - Decode the JWT from `openid4vpRequest.request`
   - Extract `expected_url` claim from payload
   - If `expected_url` is missing in signed request, return error (PROT-05)
   - Compare `expected_url` to `followUpRequestUrl` (exact string match)
   - If mismatch, return `{ valid: false, error: 'invalid_request', errorDescription: 'expected_url mismatch' }` (VP-04)
   - If match, return `{ valid: true }`

3. Export the function and types from the module.

4. Update zOpenid4vpRequest schema to document expected_url:
   - Add comment explaining expected_url is in the signed JWT, not top-level

NOTE: This function is for WALLET use - the wallet calls this to validate the AS's OpenID4VP request before responding. It doesn't modify the send function itself, but provides validation utility.
